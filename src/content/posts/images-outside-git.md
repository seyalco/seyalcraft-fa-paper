Git برای نگه‌داری تاریخچه‌ی فایل‌های پروژه فوق‌العاده است؛ اما این به معنی آن نیست که باید هر فایلی را داخل Git قرار دهیم.

تصاویر، فایل‌های صوتی و ویدئوها می‌توانند به‌سرعت حجم یک مخزن را زیاد کنند.

برای یک وب‌سایت شخصی، راه ساده‌تر این است که خود محتوا را در Git نگه داریم و فایل‌های سنگین‌تر را در یک فضای ذخیره‌سازی جدا قرار دهیم.

مثلاً در Markdown می‌توانیم به جای نگه‌داشتن تصویر در repository، فقط آدرس آن را بنویسیم:

```md
![یک تصویر نمونه](https://example.com/image.webp)
```

در این حالت Git همچنان تاریخچه‌ی نوشته را نگه می‌دارد، اما فایل تصویر بخشی از تاریخچه‌ی Git نیست.

### یک مزیت جالب

این جداسازی فقط مسئله‌ی حجم نیست.

فرض کنید بعداً بخواهیم تصویر را با نسخه‌ی جدیدتری جایگزین کنیم. اگر آدرس تصویر را ثابت نگه داریم، می‌توانیم فایل موجود در فضای ذخیره‌سازی را عوض کنیم، بدون اینکه لازم باشد خود نوشته را تغییر دهیم.

این مدل برای فضاهای ذخیره‌سازی سازگار با S3 هم به‌خوبی کار می‌کند.

البته این روش همیشه بهترین انتخاب نیست. اگر یک پروژه به قابلیت‌هایی مثل نسخه‌بندی دقیق همه‌ی دارایی‌ها یا build کاملاً قابل بازتولید نیاز داشته باشد، نگه‌داری فایل‌ها در repository ممکن است منطقی‌تر باشد.

اما برای یک وب‌سایت شخصی که نوشته‌ها مرتب تغییر می‌کنند، جدا کردن محتوا از فایل‌های سنگین می‌تواند یک معماری بسیار ساده و کم‌دردسر باشد.
