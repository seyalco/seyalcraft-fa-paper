# Seyalcraft Fa Paper

یک قالب ساده و فارسی برای ساخت وب‌سایت شخصی، وبلاگ و انتشار نوشته‌های کوتاه با [Astro](https://astro.build).

این پروژه بر پایه‌ی [Astro Paper](https://github.com/satnaing/astro-paper) ساخته شده و با هدف ایجاد یک پایه‌ی ساده، سبک و قابل شخصی‌سازی برای وب‌سایت‌های فارسی توسعه داده شده است.

## فلسفه پروژه

این پروژه قرار نیست از همان ابتدا یک طراحی کامل و غیرقابل‌تغییر به شما تحویل بدهد.

تمرکز اصلی روی **کارکرد، سادگی و آزادی در شخصی‌سازی** است.

ایده این است که ابتدا یک پایه‌ی سالم برای نوشتن و انتشار داشته باشیم؛ بعد بتوانیم ظاهر سایت را مطابق نیاز خود تغییر دهیم.

بنابراین ظاهر فعلی عمداً ساده نگه داشته شده است. شما می‌توانید رنگ‌ها، فونت‌ها، فاصله‌ها، اجزای صفحه و سایر بخش‌های رابط کاربری را تغییر دهید، بدون اینکه ساختار اصلی انتشار محتوا را از نو بسازید.

## امکانات

* پشتیبانی از محتوای فارسی و راست‌به‌چپ
* نوشتن مطالب با Markdown و MDX
* وبلاگ با صفحات مستقل برای هر نوشته
* سیستم Tag برای نوشته‌ها
* RSS و Sitemap
* جست‌وجوی محلی با Pagefind
* بخش Threads برای نوشته‌های کوتاه
* نمایش محتوای طولانی Threads با امکان باز کردن ادامه
* پشتیبانی از لینک‌های خارجی در Threads
* تولید سایت استاتیک با Astro
* امکان انتشار روی Cloudflare Workers
* امکان نگهداری تصاویر و فایل‌های سنگین خارج از Git
* TypeScript، ESLint و Prettier برای کنترل کیفیت کد

## پیش‌نیازها

برای اجرای پروژه به موارد زیر نیاز دارید:

* Node.js `22.12` یا جدیدتر
* pnpm

اگر pnpm را نصب ندارید:

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

سپس نسخه Node.js را بررسی کنید:

```bash
node --version
```

باید نسخه‌ای برابر یا بالاتر از `22.12.0` داشته باشید.


## نوشتن یک پست

پست‌های وبلاگ در این مسیر قرار دارند:

```text
src/content/posts/
```

برای مثال:

```text
src/content/posts/my-first-post.md
```

یک پست معمولی می‌تواند چنین ساختاری داشته باشد:

```md
---
author: Your Name
pubDatetime: 2026-10-04T10:00:00+01:00
title: عنوان نوشته
description: توضیح کوتاه درباره نوشته
tags:
  - نویسندگی
  - وب
---

متن نوشته از اینجا شروع می‌شود.

می‌توانید از Markdown استفاده کنید.

## یک عنوان دیگر

و ادامه‌ی متن...
```

پس از ساخت فایل، Astro آن را به‌عنوان یک نوشته شناسایی می‌کند و هنگام build صفحه‌ی مربوط به آن را تولید می‌کند.

### تاریخ و زمان

`pubDatetime` باید یک تاریخ معتبر باشد. برای مثال:

```yaml
pubDatetime: 2026-10-04T10:00:00+01:00
```

اگر نوشته را بعداً ویرایش کردید و می‌خواهید زمان ویرایش نیز نمایش داده شود، می‌توانید `modDatetime` را اضافه کنید:

```yaml
modDatetime: 2026-10-05T14:30:00+01:00
```

## Threads

محتوای کوتاه در این مسیر قرار دارد:

```text
src/content/threads/
```

هر Thread یک فایل Markdown مستقل است.

برای مثال:

```text
src/content/threads/0017.md
```

ساختار آن:

```md
---
id: 17
createdAt: 2026-10-04T12:00:00+01:00
---

این یک نوشته کوتاه است.

می‌توانم آن را در چند پاراگراف ادامه بدهم و لینک هم اضافه کنم.

https://astro.build
```

عدد `id` باید یکتا باشد.

برای ایجاد Thread جدید، کافی است یک فایل جدید با شماره‌ی بعدی ایجاد کنید.

## تصاویر و فایل‌های رسانه‌ای

لازم نیست همه‌ی تصاویر وب‌سایت را داخل Git نگه دارید.

برای تصاویر بزرگ یا تعداد زیادی فایل رسانه‌ای، می‌توانید از یک سرویس ذخیره‌سازی سازگار با S3 استفاده کنید؛ برای مثال Cloudflare R2.

در این روش:

```text
Git repository
├── Markdown
├── Astro code
└── configuration

External storage
├── images
├── videos
└── other large assets
```

در Markdown فقط URL تصویر را قرار می‌دهید:

```md
![توضیح تصویر](https://example.com/images/example.webp)
```

این روش چند مزیت دارد:

* حجم مخزن Git کمتر می‌ماند.
* فایل‌های رسانه‌ای تاریخچه‌ی Git را سنگین نمی‌کنند.
* می‌توانید فایل‌های تصویری را مستقل از کد مدیریت کنید.
* تغییر یک تصویر لزوماً نیازمند commit جدید در مخزن نیست.

به همین دلیل، برای پروژه‌هایی که تصاویر زیادی دارند، بهتر است Git را بیشتر به‌عنوان محل نگهداری **کد و محتوای متنی** در نظر بگیرید.

## Build

برای بررسی پروژه و ساخت نسخه‌ی نهایی:

```bash
pnpm build
```

این دستور چند مرحله را انجام می‌دهد:

1. بررسی TypeScript و محتوای Astro
2. ساخت سایت با Astro
3. اجرای Pagefind روی خروجی سایت
4. قرار دادن فایل‌های جست‌وجو در `public/`

خروجی نهایی در این مسیر قرار می‌گیرد:

```text
dist/
```

برای اجرای نسخه‌ی ساخته‌شده به‌صورت محلی:

```bash
pnpm preview
```

## انتشار روی Cloudflare Workers

این پروژه برای انتشار به‌عنوان Static Assets روی Cloudflare Workers تنظیم شده است.

تنظیمات فعلی در:

```text
wrangler.jsonc
```

قرار دارند.

در حال حاضر Worker به این شکل تنظیم شده است:

```jsonc
{
  "name": "seyalcraft-fa",
  "main": "src/worker.ts",
  "compatibility_date": "2026-10-01",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS"
  }
}
```

### ساخت نسخه‌ی نهایی

ابتدا:

```bash
pnpm build
```

سپس با Wrangler منتشر کنید:

```bash
pnpm exec wrangler deploy
```

یا اگر Wrangler را به شکل global نصب کرده‌اید:

```bash
wrangler deploy
```

Wrangler فایل‌های موجود در `dist/` را به Cloudflare Workers Assets منتقل می‌کند و Worker را منتشر می‌کند.

### ورود به Cloudflare

اگر هنوز Wrangler به حساب Cloudflare شما متصل نشده است:

```bash
pnpm exec wrangler login
```

مرورگر باز می‌شود و می‌توانید حساب Cloudflare خود را مجاز کنید.
